# План: совместимость VSCode-расширения с `ai-serve`, MCP-инструменты редактора, библиотека доступа

> Статус: реализация завершена. Сделано: C1–C5, A1–A9, B1–B3, F1. Дальше: нет — план закрыт.
> Репозитории-владельцы коммитов:
> - `C:\Projects\Universal-AI\submodules\u2ai-server` — пакет `@u2ai/server` (сервер, шина, MCP, агент);
> - `C:\Projects\Universal-AI\submodules\u2ai-{webdev,decomposer,measurer,images}` — копии библиотеки доступа;
> - `C:\Projects\VSCodeExtension` — расширение редактора.
> Пуш не делаем: один коммит на шаг, локально.

## 1. Задача

Три части работы.

**Часть A — совместимость расширения с `ai-serve`.**
Расширение `C:\Projects\VSCodeExtension` сегодня говорит только с монолитом `ai serve`
(протокол 0.2, домашний каталог `~/.ai-agent`). Новый сервер — пакет `@u2ai/server`
(`ai-serve serve`, протокол 0.3, домашний каталог `~/.ai-serve`) — поднимает шину, HTTP-часть
и MCP, но агента за шиной нет: `onStart` в `src/cli.js` бросает
«The agent of the server is not built yet.». Расширение должно работать с обоими серверами.

**Часть B — VSCode как источник своих MCP-инструментов.**
Только у расширения есть доступ к API редактора: `vscode.workspace.fs` и терминал VSCode.
Эти инструменты должны быть доступны другим ИИ-системам (webdev, measurer, decomposer)
двумя способами: отдельным MCP-сервером расширения (stdio) и через проксирование
доступа через `ai-serve` (шина + MCP-сервер пакета).

**Часть C — библиотека `src/access/*` в каждом подмодуле.**
Общая библиотека доступа: файловая система и запуск команд поверх сменного «бэкенда».
По умолчанию — нативный Node.js; альтернативные реализации подставляются снаружи.

## 2. Принятые решения

| Вопрос | Решение |
| --- | --- |
| Где живёт MCP-сервер расширения | **Оба варианта**: stdio-сервер в расширении + прокси через `ai-serve` |
| Форма библиотеки доступа | **Копия `src/access/*` в каждом подмодуле** (без межпакетных зависимостей) |
| Охват подмодулей | **5 подмодулей с `package.json`**: server, webdev, decomposer, measurer, images |
| Владелец агентного исполнения | **Пакет `@u2ai/server`** — агент переезжает в пакет, монолит отдаёт ему дела |

Дополнительно:

- Домашние каталоги сервера различаются, поэтому расширение читает **оба**:
  `AI_SERVE_HOME`/`~/.ai-serve` — первый, `AI_AGENT_HOME`/`~/.ai-agent` — второй.
- Контракт `serve.json` расширяется, а не ломается: старые поля (`pid`, `url`, `token`)
  остаются, добавляются `httpURL`, `complete`, `structure`, `completeWs`, `mcp`, `protocol`.
- Инструменты редактора публикуются в шине новым кадром `tools.register`
  (протокол 0.4); сервер 0.3 такой кадр отвергнет — расширение переживает это
  без падения и продолжает работать как раньше.
- Порядок работ: сначала библиотека доступа в пакете (это опора для агента),
  затем агент и протокол в пакете, затем расширение, затем MCP-инструменты.

## 4. Проверка

- Пакет: `npm test` (`node --test --test-timeout=60000 "test/*.test.js"`), `npm run check`,
  `npm pack --dry-run`.
- Расширение: `npm test` (`@vscode/test-cli`), сборка `node esbuild.js`.
- Ручные проверки — только через `AI_SERVE_HOME`/`AI_AGENT_HOME` на временном каталоге:
  рабочие `~/.ai-serve` и `~/.ai-agent` не трогаем.
- Тесты HTTP/WS обязаны закрывать сервер, иначе процесс не завершается.

## 5. Риски

- **Агент пакета беднее монолита.** У монолита команды `ask|run|chat|image` с полным
  потоком событий и генерацией картинок; в пакете картинки не поддерживаются —
  команда `image` отвечает понятным предупреждением.
- **Кадр `tools.register` меняет протокол.** Сервер 0.3 такой кадр отвергнет; расширение
  должно пережить отказ и продолжить работу.
- **Расхождение домов.** Расширение читает два каталога; приоритет — `ai-serve`.
- **Две реализации доступа.** Копия библиотеки в пяти пакетах разъедется, если править
  её в одном месте; правки идут в `u2ai-server` первыми, остальные — копией.
