# Интерактивное управление ai-webdev

## Согласованный scope

- CLI принимает задачу из аргументов; если задача не указана — использует piped stdin как задачу. Если задача уже дана, stdin добавляется как контекст.
- В TTY без задачи CLI предлагает её ввести, затем держит интерактивный канал открытым во время прогона.
- JSON и non-TTY не блокируются ожиданием оператора.
- Свободный ввод оператора становится steering-контекстом для следующей безопасной итерации активной роли.
- `ask_user` показывает вопрос и ждёт ответа через тот же интерактивный ввод; ответ не дублируется как steering.
- `/skip` пропускает текущую стадию или шаг плана; `/skip <имя>` ставит ожидающую стадию или шаг на пропуск. Пропуск применяется на безопасной границе, отражается в прогрессе/отчёте и не считается успешной работой.
- `/help` показывает команды управления, `/quit` завершает прогон.
- Каталоги `Hubfolio-2` и `Hubfolio-3` не изменять.

## Примечания реализации

- В CLI уже есть `--route` и `--stop-after`; интерактивный `/skip` должен дополнять их, а не менять их смысл.
- Подэтапы внутри роли исполняются в `runRole`; ввод можно принять на границе каждого tool round-trip, не обрывая уже выполняемый инструмент/API запрос.
- Для корректного skip активной стадии нельзя уничтожать её выполнение посреди записи. Управляющие сигналы применяются после возврата текущей стадии; пропуск шага плана применяется на границе итерации/шага, насколько это позволяет stage API.
